## 동차 좌표

- (x, y) → (x, y, 1). 원소를 하나 추가하는 이유: 평행이동까지 행렬 곱으로 표현하려고
- (x, y, w)는 일반 좌표 (x/w, y/w). 배수가 같으면 같은 점: (2, 4, 2) = (1, 2, 1)
- w = 1로 두는 이유: 나눗셈 없이 앞 두 값을 바로 (x, y)로 읽을 수 있어서 (편리성)
- w = 0 → 이상점(무한원점) = 위치가 아니라 방향
- 평행이동 행렬은 점(w = 1)은 옮기고, 방향(w = 0)은 그대로 둔다

## 왜 2×2로 평행이동이 안 되나

- 2×2 행렬은 원점 (0, 0)을 항상 원점으로 보냄
- 평행이동은 원점도 옮겨야 함 → 3×3 동차 좌표 필요

## 2D 변환 계층 (아래로 갈수록 자유도↑, 보존↓, 위 변환은 아래 것도 다 보존)

| 변환 | 자유도 | 새로 보존하는 것 |
|---|---|---|
| 평행이동 | 2 | 절대 방향 |
| 강체 (회전+평행이동) | 3 | 길이 |
| 닮음 | 4 | 각도 |
| 아핀 | 6 | 평행성 |
| 투영 | 8 | 직진성 |

- 투영은 곱한 뒤 w ≠ 1이 됨 → 반드시 w로 나눠야 진짜 위치 (new / new[2])

## "방향"의 두 의미

- 절대 방향: 어디를 향하냐. 회전하면 바뀜 (F가 눕는 것)
- 감김 방향: 어느 쪽으로 도냐. 회전해도 그대로, 반사하면 바뀜 (F가 ꟻ가 되는 것)
- det R = +1 → 면적 보존 + 감김 방향 보존. 길이 보존은 det가 아니라 RᵀR = I에서 나옴

## 변환 합성

- 행렬 곱은 오른쪽부터 적용 (pts에 가까운 것이 먼저)
- 점 c 중심 회전 = T(c) @ R @ T(−c)
- 여러 변환도 곱해서 3×3 하나로 합칠 수 있음

## 좌표계 두 개

- 수학 좌표 (scatter): 원점 왼쪽 아래, y 위로 증가
- 이미지 좌표 (img[y, x]): 원점 왼쪽 위, y 아래로 증가
- 이미지 좌표에선 같은 회전 행렬이 화면상 반대 방향으로 도는 것처럼 보임 → 실제 이미지 변환할 때 주의

## 휜 화면과 변환의 한계

- 5개 변환 모두 직선 → 직선. 휜 선을 직선으로 펼 수 없음
- 원통형으로 휜 화면 보정 → 비선형 변환 필요 (메쉬 워핑, 픽셀별 매핑)
- 투영은 평평한 화면을 비스듬히 볼 때(키스톤) 사용. 휜 화면도 작은 조각 단위로는 투영으로 근사 가능

## 3D 직선

- r = p + λd: 점 p에서 방향 d로 λ만큼 간 점
- d는 w = 0인 이상점 (방향)
- 시청자 눈에서 화면으로 가는 시선(광선) 표현에 사용 예정 (휜 화면과의 교점)

## 순방향 vs 역방향 매핑

- 순방향: 원본 칸마다 H로 출력 위치 계산 → 밀어 넣기. 출력에 구멍·겹침이 생김
  - 구멍의 근본 원인은 반올림이 아님. 2배 늘리면 원본 0,1,2 → 출력 0,2,4로 정수여도 1,3이 빔
- 역방향: 출력 칸마다 H⁻¹로 원본 위치 계산 → 가져오기. 출력 칸이 빠짐없이 채워짐
  - 대신 원본 위치가 소수 → 보간 필요
- meshgrid 격자 자체는 어느 이미지 것도 아님. 순방향에선 원본 칸 목록, 역방향에선 출력 칸 목록으로 씀

## 보간

- 최근접: 반올림. 빠르지만 계단·블록 현상
- 쌍선형: 주변 4칸 가중 평균. 선형 커널 h(d) = 1 − |d| (|d| < 1)를 가로 2번, 세로 1번
  - 매끈하지만 살짝 흐려짐 (보간의 기본 트레이드오프)
  - i+1, j+1을 읽으므로 유효 범위가 x < w−1, y < h−1
- 테두리 계단은 보간이 아니라 ok 마스크가 칸 단위로 잘라서 생김
- 계산은 실수로, 반올림은 마지막에 한 번 (uint8에 넣으면 버림 → 평균 0.5 어두워지는 치우침)
- 비교할 땐 imshow에 vmin=0, vmax=255 고정, 숫자 비교는 두 방법 모두 유효한 영역에서만

## 원통형 휜 화면: 시뮬레이션과 보정 (2026-11-08)

### 시뮬레이션 vs 보정
- 시뮬레이션: 휜 화면에 원본을 띄웠을 때 시청자 화면에 어떻게 보이는지 확인
  - 시청자 칸 (u, v)에 화면 (x, y)의 값을 가져옴 → remap 표는 역방향 F⁻¹
- 보정: 휜 화면에서도 원본이 시청자 화면에 그대로 보이도록, 화면에 띄울 이미지를 만듦
  - 화면 칸 (x, y)에 원본의 (u, v) = F(x, y) 위치 값을 가져옴 → remap 표는 순방향 F
- remap 규칙: 표에는 항상 "출력 좌표 → 가져올 입력 좌표"를 넣는다
- 검증 흐름: 원본 → 보정 → 시뮬레이션 → 원본과 비교

### 좌표 정의
- (x, y): 휘기 전 화면 좌표, 중심 기준(px). 중심 = ((W−1)/2, (H−1)/2) = (199.5, 149.5)
- (X, Y, Z): 휜 뒤 3D 좌표. Z는 시청자에게서 멀어지는 쪽이 +
- (u, v): 시청자 이미지 좌표(px), 원본과 같은 크기 H × W
- 원통 중심 (X, Z) = (0, R), 시청자 눈 (0, 0, −D)

### F: screen_to_view (cylinder.py)
- θ = x / R
- X = R sin θ, Y = y, Z = R(1 − cos θ)
- u = D·X / (D + Z), v = D·Y / (D + Z)  (위·옆에서 본 닮음)
- 화면 끝으로 갈수록 u < x, v도 작아짐 → 가로·세로 모두 휘는 2D 왜곡

### F⁻¹: view_to_screen (cylinder.py)
- u는 x에만 의존 → x 먼저, 그다음 y
- u 식을 정리하면 a sin θ + b cos θ = c
  - a = DR, b = uR, c = u(D + R)
- 삼각함수 합성: r = √(a² + b²), φ = arctan2(b, a) → θ = arcsin(c / r) − φ, x = Rθ
- y = v(Z + D) / D, Z = R(1 − cos θ)
- arcsin은 해가 두 개일 때 앞쪽(보이는) 점을 돌려줌. 화면이 접점보다 덜 감겨 있으면 문제없음
- c / r > 1이면 해 없음(nan): |u| > RD / √(D² + 2DR) ≈ 237 px (R = 300, D = 1000), 눈에서 원통에 접하는 선 바깥

### 검증: 왕복 오차
- 입력: tx = np.linspace(-200, 200, 2000), ty = np.linspace(-200, 200, 2000), R = 300, D = 1000
- tx → F → F⁻¹ → x̂, |tx − x̂|와 |ty − ŷ|의 최댓값
- 최대 오차 x: 1.4 × 10⁻¹³ px, y: 5.7 × 10⁻¹⁴ px → 시뮬레이션 도구 오차는 기준(1 px)에 비해 무시 가능
- 한계: tx와 ty를 같이 움직여서 대각선 위의 점들만 비교함. 화면 전체 확인은 meshgrid 격자로 다시 할 것

### 실험 설정
- W × H = 400 × 300, R = 300, D = 1000 (px)
- 화면 끝 각도 θ = 199.5 / 300 ≈ 0.67 rad(약 38°), 접점 각 약 77°
- R > W/π ≈ 130 유지 (θ < 90°)
- 보정 크기 방식: 원본을 원래 크기로 두고 양 끝은 잘림 (원본 축소 방식은 안 씀)

### 보정 결과 (correct_cylinder.py)
- 입력: 40 px 간격 격자
- 세로선 간격이 양 끝으로 갈수록 넓어지고, 가로선이 양 끝에서 위아래로 벌어짐 → 미리 넓히기 확인
- 끝쪽 선이 두껍고 흐림: 1 px 선이 늘어나며 보간으로 번짐 (정상)

### 시뮬레이션 (simulate_cylinder.py, 11/10 완료)
- 유효 영역 mask (H, W) bool: nan 아님 & 0 ≤ map_x < W−1 & 0 ≤ map_y < H−1
  - nan 아님: arcsin 범위 밖(c / r > 1, 해 없음) 칸 제외. nan은 비교에서 항상 False라 범위 조건만으로도 빠지지만, 읽기 쉽게 따로 적음
  - W−1 미만: bilinear가 i+1, j+1 칸도 읽음
- 처리 순서: mask 만들기 → False 칸 좌표를 0(안전값)으로 → 보간 → False 칸 검정
- 결과: 원본 격자 → 좌우 검정 띠(화면이 u ≈ 25 ~ 374에만 보임)와 오므려진 격자 / corrected → 40 px 간격 반듯한 격자

### 코드 메모
- 자료형: 이미지 값 uint8 / 계산 실수형 / 인덱스 int (uint8 인덱스는 255에서 넘침)
- 인덱스 변환: np.floor(x).astype(int) (astype만 쓰면 음수에서 floor와 다름)
- 보간 결과 → uint8: np.round 먼저 (astype은 버림)
- 괄호: 동작이면 괄호 arr.max(), arr.astype(int) / 정보면 없음 arr.shape, arr.dtype
  - "is not callable" → 괄호 빼기, "builtin_function_or_method" → 괄호 붙이기
- 배열 조건: (조건) & (조건), and와 0 <= a < b는 배열에서 안 됨
- nan은 어떤 비교도 False
- 함수 안에서는 함수가 받은 것만 쓰기 (밖의 original, H, W를 쓰면 에러 없이 틀린 결과)

## 위치 오차 측정 (2026-11-10)

### 개념: 피라미드 비유 (내 설명)
- 보여주고 싶은 그림(원본)을 종이(화면 이미지)에 그려서 원통에 감아 보여준다고 하자
- 보정 없음: 원본을 종이에 그대로 그림(종이 104번에 원본 104번). 감으면 종이 104번이 시청자에게 100번 위치로 보임 → 전체가 오므려져서 원래 모양이 아님
- 보정: 감았을 때 원래 모양이 나오게 그림. 종이 104번은 시청자에게 100번 위치로 보이니까, 종이 104번에 원본 100번을 찍음
- 종이 번호 x는 픽셀 이름표라서 휘어도 그대로. 바뀌는 건 공간 위치와 시청자에게 보이는 위치

### 정의
- 원본: 보여주고 싶은 그림 (안 바뀜)
- 화면 이미지: 휜 디스플레이에 띄운 것 (보정 없음이면 원본, 보정이면 corrected)
- 시청자 이미지: 시청자 눈에 보이는 모습, 좌표 (u, v)
- F(x): 종이 x번이 시청자 어디에 보이나 (휜 화면이 정함, screen_to_view)
- F⁻¹(u): 시청자 위치 u에 보이는 건 종이 몇 번인가 (view_to_screen)
- G(x): 종이 x번에 원본 몇 번을 찍었나 (보정 방법이 정함)
  - 보정 없음: G(x) = x
  - 정확한 보정: G(x) = F(x)
  - 호모그래피·메쉬 워핑: F를 근사한 G

### 오차 식
- 위치 오차 = |G(F⁻¹(u)) − u| (2D는 √(Δx² + Δy²))
- 순서: 시청자 칸 u → 보이는 종이 번호 F⁻¹(u) → 거기 찍힌 원본 번호 G → u와 비교
- 이미지 없이 좌표만으로 계산. 보간·반올림은 밝기만 바꾸고 위치는 안 바꾸므로 위치 오차에 안 들어감
- 차이를 재는 거라 중심 기준이든 픽셀 번호든 같은 기준이면 결과 같음

### mask
- 시청자 칸 중 종이가 실제로 있는 칸만 평가 (x, y 기준으로 만듦, G 기준 아님)
- R, D, 크기로만 정해지므로 모든 보정 방법에 같은 mask를 씀 → 공정한 비교

### 결과 (R = 300, D = 1000, 400 × 300, mask 안)
| 방법 | 평균 (px) | 최대 (px) | 비고 |
|---|---|---|---|
| 보정 없음 | 5.79 | 26.8 | 베이스라인. 최대는 화면 모서리(가로 약 25.5 + 세로) |
| 정확한 보정 (G = F) | 1.3 × 10⁻¹⁴ | 6.4 × 10⁻¹⁴ | 구현 검증 + 이상적 상한. 같은 F로 문제를 만들고 풀었으므로 0은 당연 → 보정 방법의 성능 아님 |
| 전역 호모그래피 | | | 다음 |
| 메쉬 워핑 N×N | | | 다음 |

### 화질 지표 (보조, 아직 안 함)
- 위치가 맞아도 흐려지면 보정이라 할 수 없음 → PSNR·SSIM을 보조 지표로 같이 기록
- 주의: corrected_viewed는 보간을 두 번 거침(보정 + 시뮬레이션). 시뮬레이션 보간은 실제 눈에선 없는 흐림이라, PSNR은 정확한 보정 경우를 기준으로 두고 상대 비교할 것

### 코드 구조
- common/interpolation.py: bilinear (범위 검사 안 함)
- cylinder.py: screen_to_view(F), view_to_screen(F⁻¹)
- correct_cylinder.py: make_corrected(img, R, D) → 보정 이미지
- simulate_cylinder.py: make_view_maps(H, W, R, D) → (map_x, map_y, mask), make_viewed(img, R, D) → (viewed, mask)
- eval_cylinder.py: 위치 오차 계산
- verify_warp_cylinder.py: 원통 map으로 bilinear vs cv2.remap 비교
- 경로: sys.path에 저장소 루트를 __file__ 기준으로 추가 (실행 위치와 무관). sys.path.append('common')은 실행 위치에 따라 실패함
