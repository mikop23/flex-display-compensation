# Flex Display Compensation

휘고 늘어나는 디스플레이의 기하 왜곡과 휘도 불균일을 보정하는 **시뮬레이터**를 직접 만들고,
그 안에서 하드웨어 해법(기판 구조, 소자, 광학)을 파라미터로 실험해서
"소프트웨어가 어디까지 보정하고, 하드웨어가 무엇을 받쳐줘야 하는지"를 수치로 분석한 뒤 **논문**으로 낸다.

**연구 질문 (초안):** 스트레처블 디스플레이에서 SW 보정만으로 화질 기준을 지킬 수 있는 변형 한계는 어디이고, HW 설계가 그 한계를 얼마나 밀어내나?

## 진행 현황

| 단계 | 메인 트랙 (SW) | 서브 트랙 (HW 연구) | 상태 |
|---|---|---|---|
| 0 | 기초 도구, 평가 모듈 (PSNR·SSIM), 선행연구 훑기 | - | 완료 (v2 추가 항목: 평가 모듈·선행연구 훑기 남음) |
| 1 | 기하 왜곡 보정 (베이스라인: 보정 없음 / 전역 호모그래피) | 오그제틱·키리가미 기판 | 진행 중 |
| 2 | 휘도·색 불균일 보정 (디무라) + 첫 실측 | 픽셀 보상 회로 | 대기 |
| 2.5 | 선행연구 조사, 연구 질문 확정 | - | 대기 |
| 3 | 변형 물리 모델링 (해석해·FEM 검증) | 중립면·구조 최적화 | 대기 |
| 4 | SW-HW 분담 분석 | 광학 보조 | 대기 |
| 5 | 논문화 (arXiv → 학회·저널) | - | 대기 |

## 증명 기준 (계속 다듬음)

- 기하 왜곡: 보정 후 픽셀 위치 오차 < 1 px
- 휘도 균일도: 보정 후 휘도 편차 ΔL < 2 %
- 색 균일도: ΔE (문헌 보고 설정)
- 적용 범위: 위 기준을 지키는 곡률 반경 / 신장률(%)
- 베이스라인 대비 개선폭
- 보정 연산량: 보상맵 크기(바이트) + 프레임당 픽셀당 연산 수 (따로 기록)
- 실측 일치도: 평면 화면은 디무라만 검증. 신장 부분은 파라미터용과 다른 문헌 데이터로 검증 (없으면 "파라미터 출처"로 명시)

- `FEEDBACK.md` 외부 피드백과 수정 기록
- `QUESTIONS.md` 나중에 볼 궁금한 것
